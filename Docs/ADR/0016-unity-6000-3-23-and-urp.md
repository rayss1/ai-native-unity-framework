# ADR-0016: Unity 6000.3.23f1 and the URP Client Baseline

Status: Accepted
Date: 2026-09-14
Decision source: Project owner explicitly requested Unity 6000.3.23f1 and URP.
Partially supersedes: the editor-version pin in [ADR-0014](0014-temporary-manual-unity-validation.md).

## Context

The project used Unity 6000.3.9f1 and the Built-in Render Pipeline even though the technology baseline selects URP. Runtime-created greybox primitives also depended on a Standard shader that was initially absent from standalone builds. The owner requested the patch upgrade and URP migration after confirming the interim shader-retention fix.

## Decision

- Pin the project and current validation entry points to Unity 6000.3.23f1, revision `09d2ecc7fb28`.
- Pin Universal RP to `17.3.0`, the version shipped by this editor. Unity resolves and locks its Core, Shader Graph and related dependencies. The packages retain their bundled Unity license notices; Unity licensing remains subject to the installed editor entitlement.
- Store one Universal Renderer and URP asset in the Client application. Select it in Graphics and every quality tier while preserving the selected quality tier and other existing quality settings. Product-specific quality profiles can be introduced when measured requirements justify them.
- Store greybox URP/Lit materials as explicit Resources assets. Runtime primitives reference those assets via sharedMaterial, so builds retain the shader dependencies without globally including every Lit variant or depending on the Built-in default material.
- Keep URP-specific asset authoring and validation in the Client Editor assembly. Shared, Server, protocol and framework public ports do not change.
- The current suite contains 51 EditMode tests, including the seven Arena gameplay tests, and two real-KCP PlayMode tests. Require zero failures or skips, a Player build and reconnect smoke. Preserve ADR-0014's exact-source evidence requirement; working-tree validation is development evidence until the reviewed source is committed and requalified.
- Previous editor/macOS/Regional evidence remains historical. It does not qualify this editor/package/source combination. Mobile IL2CPP, macOS and fixed Regional impairment validation remain separate gates.

## Alternatives and consequences

Keeping Built-in would retain the interim Standard workaround but contradict the requested/default pipeline. Switching to HDRP would add unnecessary desktop-focused requirements. URP assets and Resources material references provide a small client-only migration; retaining one pipeline for all quality tiers avoids accidental fallback to Built-in.

URP introduces package and rendering-resource dependencies and can change performance and visual appearance. These require fresh platform evidence, not inferred equivalence from the previous editor. Configuration is generated by Unity APIs through `BattleClientRendering.ConfigureUrp`; desktop builds validate the configured pipeline and materials before packaging.

## Rollback

Restore the previous ProjectVersion, package manifest/lock, Graphics/Quality settings, client composition and build configuration together, then open with the retained 6000.3.9f1 editor and reimport. Restore the prior Standard retention setting when returning to Built-in. Do not open the migrated assets in an older editor and assume downgrade compatibility. Server deployment and wire protocol are unaffected by this rendering migration.

Migration procedure and evidence: [Unity / URP migration](../Architecture/unity-urp-migration.md).
