# 客户端代码规范

状态：执行约束，2026-10-29。适用于项目自有客户端 Runtime、Editor、Tests 和示例。
第三方、协议和 Input System 生成物、Unity 自动生成工程文件不手工整理。

## 命名与排版

CSharpier 1.3.0 为唯一排版工具，4 空格、LF、目标 100 列；长字符串不强拆。
类型、方法、属性采用 PascalCase，接口以 I 开头，参数和局部变量 camelCase，
私有字段 _camelCase。每行声明一个字段。常量使用 PascalCase。
布尔名称表达 Is/Has/Can 条件；时间、角度和距离显式标注单位。
避免含糊缩写；类型显而易见时可用 var，否则写明类型。

序列化字段、Unity 回调、公开 API 和事件绑定是兼容边界，不为改名破坏它们。
既有协议 DTO 字段和测试反射定位属于兼容例外，必须在审查时注明。

## 控制流与职责

条件和循环总是使用大括号。优先前置检查与提前返回；保留短路求值、调用次数和执行顺序。
表达式体只用于简单属性、转换或无额外逻辑的转发。禁止嵌套三元表达式和隐蔽副作用。
一个方法完成一个可以清楚命名的工作，不用 partial、region 或无意义的方法隐藏混杂职责。
不设任意行数门槛；长方法必须能解释其单一职责。跨模块拆分随框架迁移进行。

## 注释与异步生命周期

英文标识符，中文说明性注释。公共框架 API 使用中文 XML，说明适用的线程、单位、
所有权、取消、失败与释放语义。注释解释原因和不变量，不逐句翻译代码。
TODO 必须关联具体问题或文档；不保留失效注释、注释掉的代码。
机器错误码、固定字节向量及外部术语保持不变。

异步任务必须有所属作用域、取消信号和异常观察。除 Unity/事件适配入口外不新增 async void。
入口捕获异常；正常退出显式等待释放，OnDestroy 仅作取消与兜底。
Unity 对象只能由主线程操作；每个资源、订阅、实例和会话均有明确拥有者。
Tick、预测和高频路径不得因整理增加 LINQ、闭包、装箱、临时集合或阻塞。

## 验收清单

- 排版与行为改动分批检查；不在整理中顺便修复已知行为问题。
- 检查命名、条件、所有权、释放、异常、取消与注释是否足以独立理解。
- 公共 API、序列化名、GUID、事件绑定、协议及执行时序保持兼容。
- 使用 `python3 tools/formatting/format_csharp.py --scope client --check`；包含未暂存新文件。
- 编译、架构和受影响测试实际执行；零发现、跳过或历史成功不视为本次通过。
- 性能敏感路径保留分配、协议固定向量和生命周期回归。
