## 实现与接口

- `TopologyClientFlow` 在动态帧读取设备，在固定 Tick 提交预测输入。`NetworkCharacterInput` 将相机相对方向转成 Arena 世界轴，发送相机目标角相对预测角的差值。跳跃和武器边沿仅在 prepare 成功后消费；失焦、UI 阻塞、暂停与重连丢弃待提交动作。
- `CharacterAnimationDriver.SetPresentationState` 和 `CharacterOrbitCamera.ConfigurePresentation` / `SetPresentationState` 是 Unity 客户端主线程表现接口，不引用网络或 Shared。原有 Motor 配置继续服务单机演示。
- `NetworkCharacterPresenter` 把预测/插值 Arena 状态映射到动画。位置仍由 `BattleClientCompositionRoot` / 远端池控制，根运动关闭。联网 Prefab 只有模型、武器和表现组件，不含 CharacterController、Motor、InputReader、Rifle 或本地 HP。
- `ArenaRemotePose.State` 是追加字段：移动连续量插值，离散生命/武器状态在渲染时间到达下一快照时切换；既有死亡/重生/传送历史重置保留。
- 复用已有 `ReliableEvent.combat_event`，不改 Schema。客户端严格解析、按 epoch 和房间序号去重，`BattleClientSession.DrainCombatEvents` 在拥有线程消费容量 256 的队列；满时丢最旧事件并计数。重连清队列，保留同房序号水位。事件只触发动画、枪口闪光与提示，绝不在客户端扣血。

应用拥有 `Resources/BattleClient/NetworkCharacter.prefab`。编辑器菜单 **AiNative > Battle Client > Build Network Character** 从已有 CharacterDemoRig 提取视觉子树，保留动画控制器、材质、枪械挂点和 IK 姿势。源角色演示不变。场景组合根运行时加载资源，因此现有 LocalMultiplayer 场景无需重新创建。

## 操作与限制

打开 `Assets/AiNative.BattleClient/Scenes/LocalMultiplayer.unity`，正常登录、组队/匹配。WASD 移动；按住鼠标右键转向/瞄准；左键开火；Space 跳跃；1/2/3 切换机枪、霰弹枪和火箭。鼠标保持解锁以支持大厅和战斗菜单。

当前保持 Arena 的 7 m/s、跳跃与下一 Tick 重生规则。本地演示的翻滚、蹲伏、近战、冲刺与本地步枪伤害没有进入网络规则。三种武器目前共用步枪模型。死亡和重生可以发生在两个快照之间，可靠事件提示保留反馈，不能靠快照生命位推断每次死亡。

### 开火修复（2026-10-16）

旧实现机枪只检查目标中心方向的 1.5° 夹角，声明的命中半径并未使用；文档此前的“命中球体”描述不准确。现在机枪使用脚底起算 1.8m 高、0.45m 半径的竖直胶囊，射线从玩家位置 +0.6m 发出，选择最近交点。霰弹先检查胶囊，未相交时保留 7° 辅助锥及原有伤害规则。历史回溯、重生保护和服务端扣血保持不变。火箭保持原有弹丸/爆炸规则。

准星固定屏幕中心。客户端沿相机方向查询可见远端角色的同规格胶囊，取最近表面内侧 2cm 为瞄准点；无目标时取 100m。发送的是从服务端射击起点指向该点的角度，消除固定 30m 投影准星造成的视差。此查询仅用于输入，不在客户端扣血；移动目标仍可能因插值和网络延迟产生偏差。该次开火修复当时没有加入服务端场景遮挡；随后训练场 v1 已加入静态地图遮挡，见下节。

最小原型换弹规则：R 键手动换弹、空仓按住开火自动换弹；各武器独立耗时 120 ticks（2 秒），期间不能发射该武器。满弹不触发、重复输入不重置倒计时；切枪不中断，重生和重新入房清除倒计时。备用弹暂不限，`ReserveAmmo` 配置不启用有限库存；HUD 明确展示此规则，尚无实时弹药数或换弹进度同步。此规则避免旧实现 40 发后永久停火，后续有限库存必须同时补快照字段与 HUD。

换弹计时纳入状态 hash，新共享几何纳入玩法源码指纹；重放格式不变，旧规则录像须使用对应旧构建验证。回滚需同步回滚客户端瞄准、服务端规则和指纹，并重新启动对局；不要混用新客户端与旧服务端来验收本次修复。

### 科幻训练场 v1（2026-10-16）

LocalMultiplayer 运行时由 `ArenaTrainingGroundPresentation` 替换原 130m 地板，生成 40×40m 可玩范围：左右蓝/橙出生标识、四组出生挡板、中央四根立柱、侧翼 0.9m 低掩体及南北绕行通道。适合 2–4 人；现有八人房间上限不变，后四个备用出生点也在地图内。颜色只作方向辨识，不增加队伍规则。场景实体与六个共享运行时材质随组合根释放，无第三方资源变更。

唯一静态几何定义是 Shared `ArenaTrainingMap`：毫米整数 AABB、平地高度 0、边界 ±20000、出生点同源。Unity 从 AABB 创建 BoxCollider，发光线条与装饰不参与碰撞。`ArenaMovement.Step` 在预测与服务端共用稳定 Y→X→Z 轴扫掠，角色碰撞采用半宽 450mm、高 1800mm 的保守直立盒体，支持停止、沿墙滑动、低箱落地与离边下落；不使用 PhysX 结果作为权威、不新增斜坡/动态刚体/寻路或玩家间碰撞。该限定静态查询是首个 Arena 的规则实现，不替代 ADR-0007 的通用物理适配器方案。

机枪与霰弹射线先按地图最近阻挡判定；霰弹辅助锥额外检查目标方向，不能绕墙伤害。火箭每 Tick 使用半径 300mm 的路径扫掠检测墙体、地面与角色；爆炸采用到目标脚底上方 600mm 点的视线判断，墙后目标不扣血。低掩体挡住该点时，头部露出也不会受到该次爆炸伤害，这是当前单采样点规则。客户端相机瞄准点同样受地图遮挡限制，最终扣血仍由服务端决定。

地图源纳入玩法指纹，旧布局录像需对应旧构建，混用旧服务器/新客户端不受支持。回滚需同步回滚 Shared 移动/地图、服务端出生与遮挡、客户端场景和指纹，并重开对局；协议字段未变。性能只做功能检查，没有声称满足平台帧率或 Tick 分位预算。

实际验证：共享玩法 Unity/.NET 各 33/33，服务端 Battle 75/75，预测适配器 .NET 56/56，场景几何与材质生命周期 PlayMode 1/1；旧 Host 套件 77/79，两个本机 Python bootstrap 用例因 `python` 不在 PATH 失败，战斗用例通过。运行时俯视截图为 `artifacts/training-map/overview.png`，原始结果在同目录。尝试独立拓扑时 23001 已被占用，启动器安全退出，未停止已有进程、未改日常数据库，因此未宣称新地图真实双客户端联机验收通过。已调整 P1 外部联机测试先走南侧通道再射击；实际运行、Player、移动端和弱网验收仍待执行。
