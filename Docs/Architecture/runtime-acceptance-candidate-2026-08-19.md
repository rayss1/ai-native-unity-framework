## Implemented candidate surface

- `server/RuntimeAcceptance.sln` builds a `net10.0` Battle Host without adding it to `AiNative.sln`.
- `AiNative.Server.Fantasy` consumes only the tracked, exact-submodule Fantasy package and confines `Session`, KCP, and Fantasy envelope types to internal adapter types. The gateway fixes the outer KCP MTU at 1150 before network creation, hard-caps physical connections at 64, and exposes the resolved MTU in acceptance evidence. Per-connection inbound and outbound queues are bounded at 256 KiB and 1,024 packets by default and surface explicit backpressure. Replaceable Snapshot traffic is held in a separate newest-only slot, so a stalled sender cannot accumulate an obsolete Snapshot chain.
- `AiNative.Server.Protocol` owns the two-byte message envelope, validates message-ID/type pairs, maps control/input/snapshot/event traffic to explicit delivery channels, rejects malformed frames, and enforces the 1,200-byte datagram ceiling without exposing Fantasy types. The additive `InputBatch` message ID 1103 coalesces at most two ordered `InputCommand` frames while preserving the original ID 1100 decoder and 60 Hz input semantics.
- The Host starts a real Fantasy KCP Gate on UDP `22000`. Readiness requires both the 60 Hz room and KCP listener; drain returns readiness 503, stops new gateway acceptance, drains connections, and then closes Fantasy with the Host.
- The composition root owns exactly one `Fantasy.config`; container deployments can replace it with a reviewed read-only mount without rebuilding the image.
- The room adapter accepts up to 64 physical connections and implements Login, JoinRoom, Input, 20 Hz Snapshot, and bounded 30-second Reconnect retention with project-owned Protobuf messages. A real KCP loopback probe disconnects and reconnects on a second physical connection and verifies the connection epoch advances.
- OTel metrics/traces are enabled with an optional OTLP endpoint. Runtime correctness does not require an exporter.
- A 64-bot synthetic room runs from monotonic absolute 60 Hz deadlines and emits 20 Hz 64-player snapshots within the 1,200-byte application frame ceiling. The same pacer drives the real-client load instead of relying on a fractional `PeriodicTimer` interval that Linux can quantize to 16 ms. Tests report P99/P99.9, slow-Tick count, and steady-state managed allocation for the synthetic gameplay core after warm-up.
- The test room encodes versioned little-endian non-physics state and places its xxHash64 in each Snapshot. Opt-in production capture records the exact accepted `InputCommand` or `InputBatch` frames to a bounded asynchronous log with source, Fantasy, protocol, configuration, RNG, Tick, and final-hash identity. The offline verifier rejects missing identities, dropped records, truncation, trailing data, malformed/out-of-order production frames, and final-hash drift.
- `server/acceptance/AiNative.RuntimeAcceptance` executes fixed-seed Regional, Degraded, and Backpressure profiles through the production Protobuf codec with recorded latency, loss, jitter, duplication, reordering, bandwidth, queue maxima, and full-Tick percentiles. The same tool parses classic PCAP captures into per-client one-second on-wire windows, including IPv4, UDP, KCP, and Fantasy overhead, and records capture SHA-256 plus datagram percentiles.
- Linux CI joins the candidate container network namespace and applies explicit `tc netem` Regional and Degraded profiles to loopback before the 64 real KCP clients connect. It retains the exact qdisc configuration/statistics and full packet capture, proves the qdisc dropped packets, and checks the 60-second measured window after a distinct ten-second warm-up. The deterministic reports remain separately marked `qualifiedSocketImpairment: false`; only the netem/PCAP reports claim socket evidence.
- The evaluation-only `/admin/kcp-load` probe opens and joins 64 real Fantasy KCP sessions, samples movement/fire Input at 60 Hz, coalesces each two consecutive frames into one 30 Hz `InputBatch`, consumes 20 Hz Snapshots, and can run for a requested measured duration of up to 60 minutes after a separate warm-up of up to five minutes. Its response records exact measured Input and batch counts plus both observed rates; CI requires 60 Hz frames, 30 Hz batches, and complete two-frame batches. Host reporting begins on a room-Tick boundary after all clients join and records exact warm-up, sample count, elapsed duration, Tick P99/P99.9, slow-Tick rate, Gameplay P99/allocation, state hash, hardware/runtime, and immutable identities.
- `infrastructure/battle-host` owns the Linux x64 production image and Compose contract. CI builds it from immutable .NET base-image digests, verifies the exact Fantasy package identity, one application config, non-root execution, .NET 10 runtime identity, the full KCP loopback, readiness/drain, and a normal SIGTERM exit within ten seconds, then uploads provenance without publishing the image.
