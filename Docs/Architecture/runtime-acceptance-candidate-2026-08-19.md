## Implemented candidate surface

- `server/RuntimeAcceptance.sln` builds a `net10.0` Battle Host without adding it to `AiNative.sln`.
- `AiNative.Server.Fantasy` consumes only the tracked, exact-submodule Fantasy package and confines `Session`, KCP, and Fantasy envelope types to internal adapter types. The gateway hard-caps physical connections at 64; per-connection inbound and outbound queues are bounded at 256 KiB and 1,024 packets by default and surface explicit backpressure. Replaceable Snapshot traffic is held in a separate newest-only slot, so a stalled sender cannot accumulate an obsolete Snapshot chain.
- `AiNative.Server.Protocol` owns the two-byte message envelope, validates message-ID/type pairs, maps control/input/snapshot/event traffic to explicit delivery channels, rejects malformed frames, and enforces the 1,200-byte datagram ceiling without exposing Fantasy types.
- The Host starts a real Fantasy KCP Gate on UDP `22000`. Readiness requires both the 60 Hz room and KCP listener; drain returns readiness 503, stops new gateway acceptance, drains connections, and then closes Fantasy with the Host.
- The composition root owns exactly one `Fantasy.config`; container deployments can replace it with a reviewed read-only mount without rebuilding the image.
- The room adapter accepts up to 64 physical connections and implements Login, JoinRoom, Input, 20 Hz Snapshot, and bounded 30-second Reconnect retention with project-owned Protobuf messages. A real KCP loopback probe disconnects and reconnects on a second physical connection and verifies the connection epoch advances.
- OTel metrics/traces are enabled with an optional OTLP endpoint. Runtime correctness does not require an exporter.
- A 64-bot synthetic room runs at 60 Hz and emits 20 Hz 64-player snapshots within the 1,200-byte application frame ceiling. Tests report P99/P99.9, slow-Tick count, and steady-state managed allocation for the synthetic gameplay core after warm-up.
- The test room encodes versioned little-endian non-physics state and places its xxHash64 in each Snapshot. Opt-in production capture records the exact accepted `InputCommand` frames to a bounded asynchronous log with source, Fantasy, protocol, configuration, RNG, Tick, and final-hash identity. The offline verifier rejects missing identities, dropped records, truncation, trailing data, malformed production frames, and final-hash drift.
- `server/acceptance/AiNative.RuntimeAcceptance` executes fixed-seed Regional, Degraded, and Backpressure profiles through the production Protobuf codec with recorded latency, loss, jitter, duplication, reordering, bandwidth, queue maxima, and full-Tick percentiles. These reports are deterministic application/codec evidence and explicitly set `qualifiedSocketImpairment` to false; they do not substitute for Linux network-namespace/socket impairment.
- The evaluation-only `/admin/kcp-load` probe opens and joins 64 real Fantasy KCP sessions, sends 60 Hz production Input frames, consumes 20 Hz Snapshots, and can run for up to 65 minutes. Host reporting excludes a declared warm-up and records exact sample count, elapsed duration, Tick P99/P99.9, slow-Tick rate, Gameplay P99/allocation, state hash, hardware/runtime, and immutable identities.
- `infrastructure/runtime-acceptance` builds an internal Linux x64 image from immutable .NET base-image digests. CI verifies the exact Fantasy package identity, one application config, non-root execution, .NET 10 runtime identity, the full KCP loopback, readiness/drain, and a normal SIGTERM exit within ten seconds, then uploads provenance without publishing the image.
